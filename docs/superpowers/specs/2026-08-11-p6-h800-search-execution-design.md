# P6 H800 自动搜索闭环设计

状态：已批准；尚未启动真实 H800 作业。

## 目标

为论文的 H800 执行线提供一个可自动化的真实搜索闭环：在维护者已经本地准备的资产上完成候选选择、训练/评测、反馈更新和结果汇总。该阶段不下载任何资产，也不将 H800 结果当作 Orin 的结果。

## 范围与非目标

- 本阶段的唯一正式执行目标是 H800。CPU 只用于公开 smoke，RTX 4090 是 P5 环境样例，二者都不构成 P6 论文执行目标。
- Orin 是后续独立执行线；不消费 H800 结果，也不阻塞本阶段的 H800 闭环实现。
- 复用现有 Stage5 的候选选择与反馈能力；新增的部分只负责把选择结果连接到本地训练、评测和可选后端步骤。
- 不下载数据、权重、ONNX、engine、TVM/TensorRT 工具链或其他资产；不把本地资产、原始日志、checkpoint、编译产物或逐轮结果提交到仓库。

## 配置边界

受版本控制的 `p6_h800_search_contract_v1` 只包含：

- `target: h800`；
- 搜索预算（`max_rounds`、`batch_size`）和候选空间；
- 脱敏资产标签及其版本、许可状态；
- seed、可公开指标名和聚合摘要规则。

Git 忽略的 `p6_h800_search.local.yaml` 必须由 `--local-config` 显式传入。它保存资产绝对路径、工作目录、训练/评测/可选 TVM 或 TensorRT 步骤的 argv 列表，以及本地结果 JSON 位置。公开契约中绝不出现这些值。

## 执行模型

执行控制器按以下状态机工作：

1. 校验公开契约与本地配置的标签、目标和步骤名称；目标不是 H800 或本地资产缺失时失败关闭。
2. 通过既有 Stage5 选择器取得一批候选。
3. 对每个候选以显式 argv、无 shell 拼接方式启动本地训练/评测以及配置的可选后端步骤。
4. 从本地结构化结果读取规定指标，拒绝缺字段、非数值或不属于当前候选的结果。
5. 将有效指标反馈给选择器并开始下一轮，直到达到 `max_rounds`。
6. 将完整原始记录留在本地输出目录，并产生固定 `p6_h800_search_summary_v1` 脱敏摘要。

任一命令非零退出、结果无效或写入失败时，控制器停止本次运行并写出 `failed` 摘要；不得把部分结果升级为完成或论文证据。

## 公开摘要

摘要只允许包含目标、代码版本、seed、资产标签、版本/许可状态、配置标签、计划与完成轮数、成功候选数、状态和契约规定的聚合指标。它不得包含绝对路径、命令行、主机/SSH 信息、原始 stderr、checkpoint 名称、逐轮原始指标、资产字节内容或 SHA-256。

`completed` 只表示本地 H800 搜索循环已按配置预算完成；它不表示 Orin 执行完成、远端 CI 通过、外部发布完成或论文结论已独立验证。

## 验证策略

- 单元测试覆盖公开契约与本地配置的严格校验、状态迁移、摘要脱敏与失败关闭。
- CLI 黑盒测试使用无 GPU 的小型假训练命令验证多轮编排；测试不接入真实资产。
- 真实 H800 作业只在维护者提供本地配置并显式调用 CLI 时运行。验收需要至少一条完成预算的真实 H800 搜索记录；未完成时 P6 保持“进行中（本地）”。
- P6 的公开交接文档和审计台账必须准确记录 H800 范围、Orin 延后、无下载和本地/公开边界。
