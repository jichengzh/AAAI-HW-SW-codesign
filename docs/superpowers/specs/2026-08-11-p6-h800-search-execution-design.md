# P6 H800 CoptV2X 完整搜索闭环设计

状态：已批准设计；尚未启动真实 H800 作业或 P6.1 实施。

## 目标

P6 验证当前仓库能够在维护者已经准备好的本地资产上，复现 CoptV2X 的 Pyramid/H800/TVM 搜索控制流，而不只是执行一批给定候选。验证对象是完整的候选生成、冷启动 cost model、预测选择、真实测量、反馈重训和预算收口闭环。

首轮固定范围为 Pyramid、H800 和 TVM。TensorRT 与 Orin 分别属于后续的独立搜索任务，不能混入本轮候选、预算或结论。

## 范围与固定语义

- 候选基因由完整 Pyramid 三段结构宽度和 `q_mode` 构成；`fp16`、`int8` 是不同候选，不是同一候选的两条测量臂。
- 后端是搜索任务的固定条件。首轮任务只接收 TVM 候选；不得为同一轮调用或比较 TensorRT。
- 搜索预算与 CoptV2X 主搜索一致：4 轮、每轮 4 个候选、总计 16 个候选。每轮的 4 个候选必须互异。
- 冷启动集复用维护者已在本地取得的 Gold176 测量与图特征；本轮重新训练 cost model，但不重测这 176 条记录。
- 每个被选候选都必须重新完成结构化剪枝、微调、checkpoint 选择、ONNX 导出、其定义精度的 TVM 编译与真实评测。不得将历史 checkpoint、代理 AP 或另一精度/后端的结果当作本候选实测。
- 每个成功候选都必须给出 `latency_ms`、`energy_j`、`ap30`、`ap50` 和 `ap70`。cost model 的选择目标保持 CoptV2X 定义：时延、能耗和 AP70；AP30/AP50 是完整实测证据的一部分，不是优化目标。

## P6.1：完整 CoptV2X TVM 搜索闭环

P6.1 使用 CoptV2X 已验证的 Pyramid 候选来源注册和单目标 Stage5 协议。结构候选来自当前三段宽度规范网格：7 × 7 × 7，共 343 个 Pyramid 结构；每个结构展开为 FP16 与 INT8 两个基因，因此固定 TVM 任务共有 686 个候选。

该协议的每轮状态转换如下：

1. **空间与来源注册。** 读取本地冷启动图特征、Pyramid 结构网格、基础模型来源和本地可物化契约，构造候选注册表。候选记录只包含结构、精度、图特征和本地物化所需的私有引用；不含任何预先可见的 AP、能耗或时延标签。
2. **冷启动拟合。** 以 Gold176 与图特征重新训练 cost model，并拟合 CoptV2X 的不确定性模型。初始训练只消费冷启动样本，不带历史在线反馈。
3. **预测与选择。** 对当前未测的 Pyramid/TVM 候选预测时延、能耗和 AP70，使用 `predicted_frontier_diversity` 策略选出四个独立候选。选择必须将 `q_mode` 视为特征和候选身份；不得要求 FP16/INT8 配对，也不得按量化精度分配配额。
4. **真实物化与测量。** 每个候选经本地执行适配器完成剪枝、微调、导出和对应 TVM 编译/运行。适配器读取完整候选请求，输出候选级终态与五项指标。
5. **原子反馈。** 仅当本轮四个候选均返回有效终态时，才对整批执行原子反馈校验。成功候选带五项有限指标；真实可行性或数值失败带明确的候选级失败原因。共享资产、命令、结果结构或身份失败不属于候选测量，必须隔离整批。
6. **重新拟合与推进。** 将释放的四条反馈加入本地在线反馈集，重新训练 cost model，再生成下一轮候选。第 4 轮完成后写入仅本地的预算终态；不生成或提交公开结果。

```text
Pyramid 结构网格 + q_mode
           │
           ▼
本地来源注册 / 候选物化契约
           │
           ▼
Gold176 + 图特征 ───► 初始 cost model 拟合
                               │
                               ▼
                    预测未测 TVM 候选
                               │
                               ▼
                 前沿 + 多样性选择四个候选
                               │
                               ▼
      剪枝 → 微调 → 导出 → TVM → AP/能耗/时延实测
                               │
                               ▼
                  四候选原子反馈 / 重新拟合
                               │
                        直至 4 轮、16 候选
```

## P6.2：框架搜索空间接入

P6.1 的 343 × 2 注册表可证明完整 CoptV2X 搜索循环可执行，但不等同于本仓库已有框架搜索空间已经成为候选来源。框架扫描与 `stage2_search_space_v1` 已能输出按结构、量化单元和硬件约束组织的搜索空间；该表示不能直接替换 Pyramid 三段宽度基因。

P6.2 在 P6.1 闭环验证之后实施一个受测转换层：

```text
框架扫描 / Stage2 搜索空间
           │
           ▼
Pyramid 可物化结构计划
           │
           ▼
CoptV2X 单候选来源注册
           │
           ▼
P6.1 已验证的冷启动—预测—测量—反馈循环
```

转换层只接收能够映射为完整 Pyramid 三段宽度、满足固定 H800/TVM 条件、并能由本地训练适配器物化的组合。无法完成映射、违反量化构建约束或缺失本地物化契约的组合必须被显式拒绝；不得静默回退到静态网格，也不得把通用 knob 组合伪装为完整 Pyramid 候选。

P6.1 成功不代表 P6.2 已完成；P6 只有在两个阶段各自通过对应验收后才可进入收口复核。

## 失败语义

每轮四个候选是原子反馈批次。

- 真实可行性失败或数值可行性失败：是候选的合法终态，携带失败原因，消耗一个预算位，并可随同本批其余终态进入反馈。
- 本地资产缺失、共享环境异常、适配器命令失败、结果 JSON 不存在或结构不完整、任一指标缺失/非有限、候选身份不匹配：整批隔离；不得释放反馈、不得重训 cost model、不得进入下一轮，且该批预算不消耗。
- 任何一轮不是恰好四条有效终态反馈时，控制器必须停止。不得以部分结果继续搜索，也不得把失败改写为完成。

## 测试与真实验收

P6.1 的离线 TDD 测试使用合成 Gold176、图特征、候选注册表和 argv 黑盒替身，验证：

- 从冷启动重新拟合到四轮/16候选的完整状态机；
- 固定 TVM、独立 `q_mode`、候选去重与不跨后端；
- 每轮四点 `predicted_frontier_diversity` 选择与反馈后的重新拟合；
- 完整五指标、四候选原子反馈、候选级终态和整批隔离；
- 不读取真实资产、不调用 GPU、不下载、不使用 shell。

P6.2 的离线 TDD 测试以 `stage2_search_space_v1` fixture 验证：可转换的 Pyramid 组合进入注册表；不完整、不可物化、非 TVM 或不满足 H800 约束的组合被明确拒绝；不得静默加入静态网格。

真实 H800 验收只由维护者显式启动，消费本地提供的配置和已下载资产。它必须实际完成 P6.1 的 4 轮、16 个候选、重新训练/微调和五指标测量。此次结果不进入 Git 或公开产物。P6.2 则在 P6.1 验证后，以同等本地边界完成框架搜索空间接入验证。
