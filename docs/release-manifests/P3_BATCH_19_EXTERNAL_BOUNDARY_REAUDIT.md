## 逐项证据与来源边界

五项都在受限本机 evidence 中保存了 P2 分类、origin、字节数对账、当前内容 SHA-256、实际输入/输出、私有调用者、公开替代物或缺口、来源/许可证结论、安全输出审查、固定 reason/evidence token 和下一阶段。4 项的本机 Git 历史作者与当前维护者配置一致；另 1 项是维护者控制的未跟踪环境声明。它们均没有嵌入第三方许可证或来源标记；本批只确认维护者有权进行发布复审，并不把任何未迁入文件视为已公开授权。

P2b 冻结 inventory 本身保存路径、origin、分类和字节数，没有每文件的历史内容 SHA-256。P3-19 因而记录当前内容 SHA-256 并对账 P2 元数据/字节数；若源文件发生变化，必须重新审计，不能把本批记录外推到新内容。

## 验证与安全结果

五项逐一完成 YAML/Python 解析；私有的 LUT/registry 纯逻辑回归为 52 passed（不写 bytecode 或 pytest cache）。公开 capability parser 与硬件扫描的替代契约为 6 passed。定向安全扫描发现并阻止了 1 个用户专属挂载路径；其余 4 项未发现个人目录、邮箱、IPv4 或凭据赋值。没有公开代码发生变更，因此本批不会声称公开全流程已经可运行。

本机生成的 5 项路径无关 HMAC ledger 检查点、inventory、decisions、当前内容 hash 和 HMAC key 均保持在权限受限目录，未提交、未推送。该检查点只证明本批记录结构与受限证据一致，不是 1,551 项的关闭账本。

## 对 P4--P6 的边界

本批准确识别了一个 P4 外部制品契约候选、一个 P5 环境候选和一个 P6 执行候选；这不是启动或完成这些阶段。P4 仍不得开始，直到所有与真实外部制品直接相关的 P3 候选均按同一逐项标准审计完毕。被阻塞的路径泄露候选也不得作为环境或执行链的隐式依赖。
