# P3-3：Stage4 纯内存闭环审计

状态：已完成（本地）；未推送、未发布。

## 目的与边界

本批次将一个 Stage4 闭环审计器迁入公开树。它只核验已传入内存的汇总、组标识和 SHA-256 一致性，以决定协议门禁是否闭合；它不读取实验目录、数据、模型、checkpoint、engine、ONNX、缓存或 `results/`，也不启动训练、评测、硬件或网络操作。

迁入的公开模块是 `framework/stage4/closure_audit_v1.py`，并新增
`tests/stage4/test_closure_audit_v1.py`。测试全部使用脱敏的合成字典，不依赖 fixture、私有输入或维护者环境。模块输出只包含门禁布尔值、逻辑策略名、组计数和传入 SHA-256 的一致性结论；不输出路径、URI、结果位置或真实实验数值。

## 审阅与脱敏决定

P2 将该候选归为 `migrate_code`。静态审阅确认其运行时只导入 Python 标准库（`collections`、`math`、`re` 和 `typing`），没有文件、网络、GPU、子进程或 shell 接口；对应私有测试也只构造内存对象。公开版本不复制私有数据、执行脚本或生成物。

该模块与 P3-2 拒绝的 Stage5 `closure_v3` 不同：它不接收或回显调用者提供的证据路径/结果路径。公开接口将可复现性输入限制为逻辑制品 ID、严格小写 64 位 SHA-256 和 `byte_exact` 状态；任何缺失、漂移或不合格哈希都会关闭 `feedback_update_reproducible` 门禁。

在迁入时补充了私有原版没有覆盖的失败关闭保护：非对象 holdout 组、非数组宽度、非数组折叠组字段，以及不可解析的随机基准成功率都不能形成有效通过结论。明确在 holdout 冻结输入中发现标签字段时仍抛出简短的 `ValueError`，阻止把带标签的独立 holdout 误作为无标签输入继续处理。

## 公开契约与复现作用

`build_stage4_closure_audit(...)` 仅在以下证据同时满足时给出
`stage4_closed: true`：

- 每个目标的值模型头与反馈更新的冻结选择一致；
- 排序器被明确拒绝，量化不确定性方法在基线、反馈和更新报告中一致；
- 非随机采集策略在基线与反馈视图都不差于随机基线；
- 四折反馈更新绑定到合成测量行的训练/校准/在线反馈来源角色；
- 四组独立 holdout 在标签可用前冻结，且不与训练或反馈组重叠；
- 必需的四项逻辑制品具有完全一致的 SHA-256；以及
- 至少一个目标存在“MAE 下降、区间不变宽、覆盖率不下降”的范围限定收益。

这只是协议闭环判断，不是论文数值、真实训练、真实硬件测量或统一多目标提升的声明。P4--P6 仍负责外部输入许可与哈希、路径解析、4090/H800 环境及真实执行 manifest；缺少它们时不得将此门禁结果升级为 `verified` 论文证据。

## 测试优先与当前验证

公开测试先以缺少模块的 `ModuleNotFoundError` 失败，再加入实现后通过。首轮审查发现 `after_feedback` 行绑定、采集数值契约和无效指标回显缺口；相应回归测试与修复已加入。最终定向套件为 `12 passed`；源树全量验证为 `378 passed`，覆盖率 **81.52%**（阈值 80%），新模块覆盖率 **90%**。Ruff、`compileall` 与 diff 空白检查均通过。独立复审确认：after 记录现要求 16 条、唯一 ID 且逐条匹配 ID→组；median 为正整数、成功率在 `[0, 1]`；候选计数为正整数；无效策略指标不会回显调用方原始值。

本批次最终工作树的匿名 ZIP 已独立 build/verify：111 个成员，SHA-256 为
`aca6c8426e5f1d413586e18e315dc4655fcc5446d90cd494d0643d1e28cea32c`。
构建器的逐成员禁用模式扫描通过。先前的 111 成员制品对应修复前代码，不作为本批次最终证据；本批次没有推送、发布或执行任何外部动作。
