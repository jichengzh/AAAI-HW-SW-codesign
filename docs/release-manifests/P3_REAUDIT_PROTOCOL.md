# P3：发布级逐项复审协议

状态：已完成（本地）。本协议替代此前仅以静态信号和批量分流形成的机械处置记录；此前记录及其全量 ledger 已从当前分支撤回，不能作为 P3、P4 或发布的依据。P3 关闭不启动 P4--P8，也不授权推送、发布或任何真实实验执行。

## 不变的冻结基线

P2b inventory 仍是唯一候选基线：SHA-256 为 `6fafdace7dc0eae3e9982763cb1c5c098c0ae83d1715af67ff1e08d7a1d12a79`，共 1,551 项。重审不改变 P2 分类，也不自动认可历史 decisions。

## 每项的最低证据

每个候选在受限本机审计记录中必须单独保存以下字段；路径、原文、维护者身份、地址、凭据和 HMAC key 不进入公开文件。

1. P2 分类、origin、当前内容 SHA-256 与冻结 inventory 的一致性；
2. 实际职责：模块/文档在完整实验中的输入、输出、调用者和是否属于公开支持链；
3. 依赖证据：静态导入、调用点、运行入口、数据/模型/硬件/生成物边界，以及公开树中等价物的具体对比；
4. 许可证与来源：作者归属、上游来源、许可证/NOTICE、修改范围和是否允许再分发；
5. 安全与隐私：内容、输出、异常和日志是否可能传播路径、身份、地址、凭据或受控实验信息；
6. 结论、固定 reason/evidence token、后续阶段、审阅日期，以及可复跑的验证命令或明确的“无可运行验证”理由。

静态扫描、AST、目录、扩展名或关键词只能产生候选线索，不能单独决定 `excluded_nonessential`、`duplicate_or_superseded`、许可证状态或 P4--P6 的归属。

## 处置规则

- `duplicate_or_superseded` 必须有公开实现的职责对比与测试/API 证据；同名、同路径或关键词相似不足以成立。
- `excluded_nonessential` 必须证明没有公开支持链调用它，并说明由什么公开流程替代其必要职责；“位于 tests/、debug/ 或 agent 目录”不足以成立。
- `external_contract_p4`、`environment_contract_p5`、`execution_contract_p6` 必须先确认候选的主导依赖；若一个候选同时跨越多个边界，记录其主导职责和其余依赖，而不是仅凭第一个命中的关键词分流。
- `blocked_license_or_permission` 必须区分许可证未知、再分发不允许、来源不明、隐私泄露和需要安全改写；阻塞不等于完成，也不等于可忽略。
- `migrated_public` 或 `rewritten_public` 只能在公开实现、测试、脱敏扫描和对应输入契约均已存在后记录。

## 批次与质量门禁

每批最多 25 项，同类候选也必须逐项记录证据。批次结束前执行：候选内容 hash 复核、公开/私有依赖反证、许可证来源复核、敏感输出审查、decision schema 校验和独立抽样复审。批次公开记录仅报告数量、类别、受控 token、通过/阻塞原因和不含路径的摘要；逐路径 evidence 仅保存在权限受限目录。

任何发现来源、许可证、私有信号或调用关系无法确认的候选保持未决，不生成全量 ledger，也不进入 P4。P4 只在真正完成 P3 的相关候选审计后开始。
